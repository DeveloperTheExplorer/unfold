# unfold

Read a large pull request as a set of small, independently assessable changes.
unfold traces changed entry points and behavioural anchors through the changed
code they rely on, producing feature and bug-fix blocks with the code beside
them. Shared contracts, helpers, and wiring appear in every block whose outcome
depends on them.

```bash
git clone git@github.com:DeveloperTheExplorer/unfold.git
cd unfold && npm install && npm link

cd ~/your-repo
unfold --pr 123      # or just `unfold` for the current branch
```

Needs Node 22.5 or newer, `git`, `ripgrep`, the Codex CLI for briefings and
explanations, and `gh` for pull requests and posting. Claude Code is supported
with `--agent claude`. Set `LINEAR_API_KEY` to
include private linked Linear issue context. See [Requirements](#requirements).

## Why it works this way

Most review tools hand the whole diff to a model up front and ask it to decide
what matters. You then read the model's opinion instead of the code, and you
have no way back to the code on your own terms.

unfold splits those jobs:

- **Coverage comes from code relationships.** Changed routes, commands, UI
  interactions, and other behavioural roots become review anchors. unfold
  follows their call and reference paths through changed symbols, including
  unchanged intermediary functions. On startup, the selected AI agent gives
  those complete candidate chunks semantic names, short analyses, and a runtime
  execution order. The model cannot omit a candidate from the plan.
- **Overlap is intentional.** A shared DTO, guard, helper, repository method, or
  registration is cloned into every affected block. Its explanation is scoped
  to that block, because the same helper can be safe in one flow and risky in
  another.
- **The first useful context is automatic.** Each chunk opens with a short AI
  description and analysis generated by the cached startup scan. Press `e` on
  a step for a deeper explanation of that code unit. Press `E` on a block and its parts
  are explained first, then assessed together as a small pull request. Answers
  cache against both the content and block context.
- **Findings stay attached to evidence.** If code in the step is unusual,
  contradictory, unsafe, vulnerable, or violates a repository practice with a
  concrete consequence, the explanation adds up to two visually distinct
  `LOW`, `MEDIUM`, `HIGH`, or `CRITICAL` findings. Each includes its kind, exact
  location, trigger, consequence, and supporting evidence. No callout appears
  when nothing actionable is visible.

## Intent before implementation

Opening a pull request starts with one or two plain-language paragraphs about
the problem and intended outcome, before the review path or code. The briefing
uses the PR title and description plus any Linear issue URLs linked from the
description. With `LINEAR_API_KEY` set, unfold reads each linked issue's title,
description, status, and project through Linear's read-only GraphQL API. Without
a credential, the PR description and ticket links still appear and review is
never blocked. The briefing is cached until its source context changes.

## Facts, not prose, where facts exist

That endpoint block is not model output. It is read out of the decorator
arguments: the route from `@Post('/x')` plus the controller's `@RestController`
base, authorization from `@GlobalScope` / `@ProjectScope`, entitlement from
`@Licensed`, throttling from `ipRateLimit` / `keyedRateLimit`, and the contract
from the `@Body` DTO and the request type. Auth comes from the route's own
`skipAuth` / `allowUnauthenticated` / `apiKeyAuth` flags.

The model is given those facts and told not to restate them, so its three
sections — **Trigger**, **Refuses**, **Hands off to** — reason from them instead
of paraphrasing the diff.

Inside a block, each code unit still asks the question appropriate to its role:

| Role | Sections |
|---|---|
| Contracts | Shape · Consumers · Constraints |
| Entry points | Trigger · Refuses · Hands off to |
| Services | Achieves · Orchestrates · Unchanged |
| Persistence | Reads and writes · Consistency · Unchanged |
| External calls | Calls · Failure |
| Wiring | Registers · At boot |
| Surface | User sees · State |
| Tests (optional appendix) | Pins · Gap |

The block itself answers **Purpose · Flow · Boundary**, then raises grounded
review findings. Opening a block immediately places its complete, multi-file
diff beside the startup analysis.

## Nothing is hidden

Every production hunk lands in at least one block. A hunk appears more than once
when multiple outcomes depend on it; the overview totals still count physical
diff lines only once. Isolated behavioural changes become their own honest
block instead of being discarded. Unclaimed import-only edits and tests sit at
the bottom as collapsed appendices and are excluded from normal navigation and
whole-change explanation. The original file-by-file tree remains behind
**Files** as the completeness backstop.

## The code that was already there

A diff shows you what changed. It does not show you what the change is standing
on. Every symbol node carries, found by ripgrep and the file's own import list:

- **The whole current body of the symbol**, with the changed lines marked, so
  you can see the branches the diff did not touch.
- **Resolved imports** the changed lines depend on, followed through relative
  paths and across workspace packages to the file and line that declares them.
- **Callers**, searched in the containing package — for a method, by its class.
- **Other uses in the same file**, and **tests** that name it.

Those relationships are also a navigation surface. A changed symbol shows a
small dependency → change → consumer trace map. Click a dependency, caller,
test, or identifier in the code pane to open the defining region, then keep
following identifiers or return to the change. Resolution uses outlines,
imports, and repository search; when there is no reliable target, unfold says
so instead of guessing.

## Ask the step you are reading

Every review step has its own question box. Follow-up answers receive that
step's diff, full symbol body, deterministic facts, dependencies, callers, and
the local conversation—not a context-free copy of the entire PR. Questions are
kept in the browser session and count as model calls; review notes remain the
persistent, exportable record.

## Independent Codex review

The **Agent review** action starts a normal, persistent Codex session in the
repository and invokes the installed `$pr-review` skill. It inherits the
user's Codex configuration and configured MCP servers, and has the repository,
shell, and Git available through Codex's auto-reviewed `workspace-write`
sandbox. This is separate from Unfold's small, restricted explanation calls.

Unfold passes its execution-ordered chunks as a coverage map, not as evidence.
The reviewer still gathers the PR and Linear context, reads repository rules,
searches callers and dependencies, and verifies every finding independently.
Findings name their relevant stable block IDs so they reappear on those chunks
inside Unfold. The result and Codex session ID are persisted; copy the resume
command from the UI to continue in the same capable session.

The same workflow is available without the UI:

```bash
unfold review --pr 123          # standard review; deep mode is chosen when warranted
unfold review --pr 123 --deep   # force the skill's deep review mode
unfold review --review-model gpt-6-astra
```

The review skill is intentionally read-only and never posts to GitHub. The
session has normal CLI capability for authorized follow-up work, but posting
still goes through Unfold's explicit notes/posting flow.

## Notes, and three ways out

Click a line number to annotate; shift-click for a range. One note store, three
exits:

```bash
unfold notes list --status open            # what you wrote
unfold notes export --format xml           # for your coding agent
unfold notes export --format md --out r.md # for a file
unfold notes post --summary "…"            # as a real GitHub PR review
unfold notes reply <id> --body "…"         # the agent answers back
unfold notes resolve <id> --body "Fixed: …"
```

Notes are keyed to a scope hash, not to a run, so they survive re-running
`unfold` on the same diff after you edit the code.

## Memory

The browser tab never receives a syntax grammar, a theme, or a token array.
Highlighting happens on the server, per hunk, cached, and the tab gets finished
HTML for the lines it is showing. Only expanded tree rows exist in the DOM.

Only expanded tree rows exist in the DOM, and rendered rows are capped at 3,000.
This matters because overlapping blocks intentionally create more logical review
nodes than there are physical diff hunks.

## Commands

```
unfold                       current branch vs merge-base, uncommitted work included
unfold main..feature         an explicit range
unfold --pr 123              a pull request, by number or URL
unfold --ref branch          ignore uncommitted work
unfold blocks [refs]         print the feature/bug blocks and exit
unfold path [refs]           alias for `unfold blocks`
unfold tree [refs]           print the file tree instead
unfold tree --json           the tree as JSON
unfold review [refs]         run Codex pr-review with the ordered chunk map
unfold review --deep         force the skill's deep review mode
unfold notes <command>       see above
```

Options: `--port`, `--no-open`, `--agent codex|claude`, `--model <name>`,
`--review-model <name>`, `--tools synthesis|all|none`, `--deep`.

Codex is the default agent and uses the Codex CLI's current default model, so
unfold does not freeze its default to a model name that will go stale. Override
the model for either agent, or switch to Claude Code explicitly:

```bash
unfold --pr 123                              # Codex, current default model
unfold --pr 123 --model gpt-6-astra          # Codex, explicit model
unfold --pr 123 --agent claude              # Claude Code, its default model
unfold --pr 123 --agent claude --model opus # Claude Code, explicit model
```

`--tools` controls whether the model may Read/Grep the repository while
explaining. `synthesis` (the default) provides the full changed symbol and its
known dependencies and callers, and also allows repository inspection for
hunks, symbols, files, packages, and the whole change when a risk needs more
grounding. `none` restricts the agent to the supplied context.

Add `.unfoldignore` (gitignore syntax) to drop generated files from analysis.
They still appear under "Excluded from analysis" so nothing is silently hidden.

## Requirements

Node 22.5+ (for `node:sqlite`), `git`, `ripgrep`, the Codex CLI for briefings
and explanations, and `gh` for `--pr` and posting. Install Claude Code only if
you use `--agent claude`. State lives under the active Git directory at
`unfold/unfold.sqlite`, including the real per-worktree Git directory when
`.git` is a pointer file. Opening unfold makes one cached model call for the
execution-ordered review plan. Pull requests make a second cached call for the
intent briefing; deeper explanations remain on demand. Linked Linear
details are fetched only when `LINEAR_API_KEY` or `LINEAR_ACCESS_TOKEN` is set.
